# Architecture

How the parts of Storage connect, and the rules that hold across all of them.

Storage targets Jellyfin 12.4 (`net10.0`, ABI `12.4.0.0`). Every event and API it uses is checked against `Jellyfin.Controller`, `Jellyfin.Data`, and `Jellyfin.Model` 12.4.0.

The API routes all sit under `Storage/`. `GET Disks` checks every disk and returns one entry per disk. `GET Format` gives the file systems this server can format and where a new disk is mounted, and `POST Format` formats a disk with nothing mounted, mounts it, and adds it to a library when one is named. `POST Folders` makes a folder at the top of a mounted disk and adds it to a library when one is named. `GET Translations` serves the page strings and is the only route that allows anonymous requests.

The dashboard pages import Base only through `storage_common.js`, which also holds the tab bar and the plugin's strings in the viewer's language. Every word a page shows comes from a key. `storage_shared.css` holds only spacing between Base components.

## State

Everything the plugin keeps sits in Jellyfin's plugin configurations folder, beside the plugin configuration and outside the install folder that an update replaces.

| File | Holds |
| :--- | :--- |
| `Jellyfin.Plugin.Storage.xml` | The Storage low and Storage full alerts, each disk's own alerts and share address by mount point, when scans are blocked, whether missing disks are remounted, and whether monitoring is paused |
| `Jellyfin.Plugin.Storage.State.json` | The mount point each library folder was last seen on, when each missing disk went missing, and each disk's state and level at the last check, and what each disk in use was mounted from with its failed remounts |

## Rules

* **Disks come from the libraries.** Every folder of every library except Collections is placed on the deepest mount point that holds it, and the folders on one mount point share a row. Every other mounted volume is listed as unused, except volumes the OS keeps for itself, such as tmpfs, `/proc`, container layers, macOS's system volumes, and anything under 1 GB.
* **Unformatted disks are read below the file systems.** On Linux, `LinuxDiskInventory` reads files only: `/sys/block` for each disk's size, model, and partitions, udev's records under `/run/udev/data` for the file system on each, and the mount table. A disk with nothing on it mounted or in use as swap, and nothing stacked on it such as dm-crypt, LVM, or RAID, is listed. It is **Unformatted** when it has no partition, partition table, or file system, and **Not mounted** otherwise, with the label and type of each file system udev saw on it, such as an installer image on a USB drive. A partition udev cannot identify still counts as data, since it may hold an encrypted volume. On macOS and Windows only unformatted disks are listed. The boot areas of an eMMC chip are left out. Without udev's records, as in most containers, none is reported. On macOS, `MacDiskInventory` calls Apple's DiskArbitration framework from C#, the framework diskutil itself uses, since the disk devices are readable only as root but their descriptions are not. It describes each whole disk in `/dev`, and counts one with no content, no partitions or volumes under it, and no file system of its own. On Windows, `WindowsDiskInventory` opens each physical disk, `\\.\PhysicalDrive0` and on, from C# and reads its partition layout, size, and model. A disk never initialized counts, and so does one with no partition besides the hidden Microsoft Reserved partition Windows adds to a new GPT disk. Reading a layout needs administrator rights, which a Jellyfin service running as LocalSystem has. Without them no disk is reported.
* **SMART health is read from C# on each OS.** On macOS, DiskArbitration finds the disk behind a mount point, the IOKit registry leads to the NVMe device, and Apple's NVMe SMART plugin returns its health log, so SATA and USB disks report none. On Linux, udisks2 already reads every disk's SMART data and lets any user read it over the system D-Bus, through Tmds.DBus.Protocol, which ships beside the plugin. On Windows, the volume behind a drive letter names its physical disk, which is asked for its NVMe health log, or for Windows' failure prediction when it is not NVMe, which needs administrator rights. Shares have no SMART data. A disk with no reading shows no health.
* **Jellyfin's own folders count too.** Program data, web, logs, image cache, metadata, cache, and transcodes, as Jellyfin's dashboard lists them, put their disk in use even with no library on it, so it is listed under Jellyfin, alerted on, and remounted. They belong to no library, never block a library scan, and are not missing before Jellyfin makes them, such as transcodes before the first transcode. Each but web, which Jellyfin only reads, is checked for writing.
* **Only disks in use are recorded and guarded.** A disk no library uses never writes an activity entry, never blocks a scan, and is never muted.
* **No disk call can hang a check.** Each folder check, volume read, and mount listing runs on its own thread through `VolumeProbe`, with a 5 second limit. A call that runs out of time marks its disk unresponsive, and is not started again until it returns.
* **A disk is missing when it left its mount point.** A folder whose remembered mount point is no longer mounted puts its disk in the missing list, even when leftover files make the folder look present.
* **A folder never seen is placed by where disks usually mount.** A gone folder under `/Volumes/<name>`, `/mnt/<name>`, `/media/<name>`, `/run/media/<user>/<name>`, a drive letter, or a network share counts as that disk missing. A gone folder anywhere else counts as a missing folder on a mounted disk.
* **One check runs at a time.** A second request waits for the first to finish. The Storage tab, the **Check storage** task, and the scan guard all run the same check.
* **A disk's own alerts replace the global ones.** A disk with an override in `DiskOverrides` is measured by its own Storage low and Storage full alerts, set from its dialog, and every other disk by the global alerts. Saving keeps one override per mount point and the Error alert past the Warning alert in each.
* **A missing disk is mounted again the way its OS does.** While a disk in use is mounted, each check records what it was mounted from. When it goes missing, the check mounts it again from the share address set in its dialog, else from what it was seen mounted from, and reads the disks once more, so a disk back in the same check records only **Disk remounted**. On macOS, `statfs` gives a share's URL and NetFS mounts it again with the password saved in the keychain, never asking. On Linux, systemd is asked over the system D-Bus to start the mount unit it keeps for an `/etc/fstab` entry. On Windows, a `\\server\share` path is its own share, `WNetGetConnection` gives the share behind a drive letter even while it is disconnected, and `WNetAddConnection2` connects it again with saved credentials. A disk the OS mounts itself, such as a local disk on macOS or Windows, or one not in `/etc/fstab` on Linux, is left alone. Every missing disk is tried at once, each within 25 seconds including a 10 second wait for it to show up. A new share address is tried at the next check. A disk is tried at three checks in a row, then after an hour, doubling up to 12 hours. Only the first failure writes **Disk not remounted**.
* **Only a disk with nothing mounted is ever formatted.** `DiskFormatting` reads the inventory again at the moment of the request and formats only a disk it lists then, so a mounted disk, the system disk, or one something is stacked on is never touched, whatever the request says. A blank disk is formatted as asked. A disk that holds data is erased only when the request says to erase it, never when /etc/fstab mounts it where a library expects a disk, since that is a library's disk that dropped off, and the dashboard asks for its device name, such as `sda`, to be typed first, where a blank disk asks for its new name. The name must be 1 to 11 letters, numbers, spaces, dashes, or underscores, so it is also a safe folder name, and a mount folder that already holds files, that a library expects a disk at, or that another /etc/fstab entry mounts at is refused. One format runs at a time.
* **Each OS formats the way its own tools do.** On Linux, udisks2 is called over the system D-Bus, as GNOME Disks does: a GPT partition table, one partition with the file system owned by Jellyfin's user, an `/etc/fstab` entry by UUID with `nofail` and `x-mount.mkdir` so it mounts at every boot and can be remounted, then a mount at `/mnt/<name>`. exFAT and NTFS keep no Linux owners, so their entry adds Jellyfin's `uid` and `gid`, or root would own the disk whenever it mounts at boot. Before anything changes, udisks is asked whether anything on the disk is mounted or in use as swap, and an erased disk's own `/etc/fstab` entries, named by UUID or device, are removed so its folder has one entry. The file systems offered are the ones udisks has the tools to make, out of ext4, XFS, Btrfs, exFAT, and NTFS. On macOS there is no public API for formatting, so `MacDiskFormatter` runs Apple's `diskutil eraseDisk`, the only outside tool the plugin runs, with a GPT map and one APFS or exFAT volume that macOS mounts in `/Volumes`. On Windows, the Storage Management API that Disk Management uses is called through Windows' WMI scripting objects: the disk is brought online, initialized as GPT, given one partition with the next free drive letter, and formatted as NTFS or exFAT.
* **A folder is made only directly on a listed disk.** `FolderCreator` takes a mount point only when the last check listed that disk as available, and a name only when it is one plain name of up to 100 characters with no path separator, no character Windows forbids, and no `.` or `..`, so the folder cannot land anywhere else. A folder already there is left alone. The folder is made as Jellyfin's own user, so a disk only root may write to refuses it with the OS's reason.
* **A new disk can join a library at once.** When a library is named, the new mount point is added to it with `ILibraryManager.AddMediaPath`, with real-time monitoring paused for a second as Jellyfin's own API does.
* **Library folders are checked for writing.** Each library folder on a mounted disk is asked, through `access` with Jellyfin's own user and without writing anything, whether Jellyfin may write there, so a read-only mount or a disk owned by another user shows in the banner and the folders table before NFO files and artwork fail to save. Windows is not checked.
* **A disk's type comes from the OS.** A disk reached over the network is **Network**. A disk plugged in from outside is **External**: on Linux, one udev marks as on USB or whose device path runs through a USB controller; on macOS, one DiskArbitration marks as not internal, leaving out disk images; on Windows, one on USB, FireWire, or an SD card reader, or marked as removable media. Any other disk is **Local**. A disk that cannot be read keeps the type it last had.
* **Disk health alerts come from SMART data.** A disk whose SMART data predicts a failure is **Failing**. A disk at or past the **Too hot** temperature, 60 °C by default, is too hot, and clears only once it is 5 °C cooler, since a disk's temperature moves a degree or two between checks. An SSD at or past the **Worn out** share of its rated life, 90% by default, is worn out. Each can be turned off, and each is recorded once when it starts, like the space alerts. A disk that reports no reading sets off none.
* **The Storage tab leads with what needs a look.** A banner lists each problem on a disk the libraries use, red when any is missing, unresponsive, failing, or full, else yellow, or says in green that every disk is healthy. Space cards add up the disks the libraries use that could be read.
* **Alerts clear with a margin.** A disk passes an alert at its point and clears it only 2 points of its share in use below it, so a disk sitting at a point is recorded once. An alert in GB free becomes a share of each disk's size.
* **The activity log records changes only.** Each check compares each disk with the last check and records a disk that went missing, became unresponsive, came back, or passed an alert. The changes of one check are summed into one entry per kind. A disk falling back below an alert records nothing.
* **A scan is stopped before it starts.** Every full library scan runs as Jellyfin's **Scan media library** task. `ScanGuard` listens for `ITaskManager.TaskExecuting`, which fires before the scan's work begins, checks the disks, and cancels the task when a disk blocks it. A check that cannot finish within 45 seconds falls back to the last finished check, or before the first one, to the disks the state file recorded as missing, which count as unsafe to scan, so a scan is never let through for want of an answer. **Block when needed** blocks only for a missing disk with a folder that still holds files, or a disk that is unresponsive, since Jellyfin itself skips a library folder that is gone or empty.
* **Real-time monitoring ignores a missing disk.** `MonitorMuter` passes each folder of a disk that cannot be read to `ILibraryMonitor.ReportFileSystemChangeBeginning`, and releases it once the disk is back.

## Limitations

* A mount point that is an empty folder on the system disk while its disk is away reads as present the first time the plugin sees it. The plugin learns the right mount point once the disk is mounted.
* Space on a Windows network path, such as `\\nas\media`, is not read.
* A refresh of one library or folder started from its menu is not a scan task, so the scan guard cannot stop it.
* On Linux, a remount needs the disk in `/etc/fstab` and Jellyfin running as root or allowed by a polkit rule to start mount units. A share that needs a password on macOS or Windows remounts only with the password saved in the keychain or Credential Manager of the account Jellyfin runs as.
* On macOS, a share that went missing before the plugin first saw it mounted is remounted only once its share address is set in its dialog, since macOS keeps no record of where an unmounted share came from.
* On Linux, formatting needs udisks2 and Jellyfin running as root or allowed by a polkit rule to manage disks. In a container there is no udisks, so no disk can be formatted. On Windows, formatting needs administrator rights.
* On macOS, a whole disk with no partition map that holds a file system macOS cannot read, such as ext4, looks the same as a blank disk, since its raw sectors are readable only as root. It is listed as unformatted, and formatting it erases it. The format dialog names the disk and asks for its new name to be typed first.
* SMART health on macOS covers NVMe disks only, and on Windows only disks behind a drive letter.
* On Windows, unformatted disks are listed only when Jellyfin runs as an administrator, such as a service running as LocalSystem. A partition with a drive letter but no file system on an otherwise partitioned disk is not listed.
